# Script 2 · ICT Sweep + Order Flow Models [NY] (02_ict_sweep_order_flow_models.pine)

Source: [`../received/02_ict_sweep_order_flow_models.pine`](../received/02_ict_sweep_order_flow_models.pine). Kind: **strategy**. Port complexity: **XL** — Four independent strategies (A and B share one sweep -> MSS -> displacement-FVG -> resting-limit engine with eight states and flip/extension rules). Five HTF requests need TradingView's lookahead_on+[1] timing (one bar later than the lab's batching) and session-aligned 5m/15m/60m/D bars. The script carries pivot and untaken-liquidity lists with caps, a persistent 1H PD-array bias machine, 1m IFVG/CISD tracking, an overnight volume-profile value area and volume-based absorption logic. Trades persist across windows and close at the next window start. The script outputs only W/L counts, so parity must be checked trade by trade on real 1m data (with volume) that the lab does not have yet.

This spec was produced by the Phase 3 intake review (every line of the script read, earlier descriptions checked against the code). Line numbers refer to the received file. Decisions referenced as D1–D13 are in [docs/13](../../docs/13-phase3-pine-ports.md).

## Setups

### Model A: 20:00 NY 15m swing-liquidity sweep -> 1m MSS -> displacement-FVG limit (long and short)

*Fully defined by the script (entry, stop and exit):* **yes**

- **Entry:** Levels: on the first 1m bar of the window (aStart l.652; run() startNow l.470-483), hi/lo = aHi15/aLo15. These are the most recently confirmed 15m pivot high/low (ta.pivothigh/low len 2/2) that no later 15m high/low has exceeded, read from the last closed 15m bar (f_liqSwings l.197-222, request l.616). The model idles that day if either level is na or hi<=lo (l.483). Sweep: a wick above hi starts a short setup and a wick below lo starts a long setup; no close-back is needed (l.517-538). It can happen on the 20:00 bar itself. While the setup is unarmed, a new extreme moves ext/extBar and resets MSS/FVG. Sweeping the opposite level flips the direction, and an outside bar that sweeps both sides ends up long because the low check runs second. MSS (long): a close above the most recent stored 1m pivot high (mssLen 2) whose pivot bar is before extBar (l.551-555, f_pivotBefore l.184-194; pivots are stored when confirmed, at bar_index-mssLen, l.726-737). Displacement FVG (long): low > high[2], gap >= minFvgTicks*mintick, and a bullish middle candle with body >= 1.5 x SMA20(body)[1] (l.163-170). Its first candle must be at or after extBar, and once MSS has happened its middle candle must be <= mssBar+3 (l.544-547). The FVG is dropped if a bar closes below its bottom (l.548-550), and the latest qualifying FVG overwrites earlier ones. Arming (l.559-565): needs MSS plus a live FVG with fvgBar <= mssBar+3. This places a resting BUY LIMIT at fvgTop (the low of the 3rd candle, 'FVG edge') or at (top+bot)/2 ('FVG 50% (CE)'), at that bar's close. Fills are checked from the next bar: low <= entry fills at min(open, entry) (l.501-505). Shorts mirror this (l.568-594) with a SELL LIMIT at fvgBot (the high of the 3rd candle) or CE, filled at max(open, entry).
- **Stop:** Stop = m.ext - slBuf for longs and m.ext + slBuf for shorts (l.561/588). m.ext is the most extreme low/high printed since the sweep. It updates until arming and is frozen once armed. slBuf = slBufTicks (0) x mintick. If the stop is touched on the fill bar, the trade is booked as a loss right away (l.508-510). On later bars the stop is checked by touch (low<=sl / high>=sl), stop first (l.458-461).
- **Target / exit:** aTgt='Opposite level' (default): TP = hi for longs or lo for shorts, if that level is beyond the planned entry and its distance >= minRR(1.0) x (entry-sl). Otherwise TP = entry +/- aRR(2.0) x risk (l.562-563, 589-590). 'Fixed RR' always uses aRR. TP is computed from the planned limit price, not the actual fill (a gap fill at the open does not move TP). TP is checked by touch from the bar after the fill and never on the fill bar (manage requires bar_index > t.bar, l.453). The only other exit is the neutral close at the next window start (l.470-472).
- **Position rules:** One cycle per window. After a fill (state 3), or after a 'missed' cancel (target touched before the limit filled, l.502, 511-512), the model idles until the next 20:00 (l.489-490). Setups that never filled (waiting for sweep, waiting for MSS, or an armed limit) are cancelled on the first bar outside the window (l.491-492), so the last bar the limit can fill on is the last in-window bar. A filled trade is NOT closed at 02:00. It runs until SL/TP or the next 20:00 window start, where it is closed 'neutral': it counts in Trades but not in W/L (l.441, 471-472). manage() runs first on that bar (l.776), so an SL/TP touch on that bar is still scored. No reversal, pyramiding or cooldown. A, B, C and D use separate Trade objects and can be open at the same time.
- **Timeframes:** Built for a 1m chart (warning at l.1010-1011). Uses 15m for the liquidity swings. All bar counts (mssBar+3 etc.) are 1m bars.
- **Sessions (New York):** Window 20:00-02:00 NY (1m bars opening 20:00-01:59), every day including Sat/Sun (ALL_DAYS ':1234567', l.27, 46, 646). Levels are frozen at the 20:00 bar from 15m data up to and including the 19:45 15m bar. Pivots need 2 confirming 15m bars, so swings from the last ~30 min before 20:00 are excluded.
- **Defaults:** entryMode 'FVG edge'; mssLen 2; dispMult 1.5; minFvgTicks 0; slBufTicks 0; minRR 1.0; useA true; aSwing 2; aWin 2000-0200; aTgt 'Opposite level'; aRR 2.0

### Model B: 08:00 NY hourly-candle range sweep + close back inside -> 1m MSS -> displacement-FVG limit (long and short)

*Fully defined by the script (entry, stop and exit):* **yes**

- **Entry:** Range: high/low of the 1m chart bars opening 08:00-08:59 NY, accumulated on chart bars rather than requested (l.786-794). It is used only if its first bar is < 24h old (bFresh l.796); otherwise the model idles. At the first bar of the 09:00-12:00 window (bStart l.653) the shared engine is reset with this range (l.797). From there it is the same engine as A (run() l.468-595: wick sweep, extreme tracking, flip, MSS on the most recent 1m pivot before extBar, displacement FVG with first candle >= extBar and middle candle <= mssBar+3) with needBack=true. Arming also needs backIn: a close back above the swept low (long, l.542-543) or below the swept high (short, l.569-570) on some bar after the latest extreme. The flag resets at each new extreme (l.524/535) and can be satisfied before or after the MSS. Order: resting LIMIT at the FVG edge (long fvgTop / short fvgBot) or CE, placed at the arming bar's close. It fills from the next bar on touch at min(open, entry) for longs or max(open, entry) for shorts (l.501-505).
- **Stop:** Sweep extreme since the sweep -/+ slBuf (l.561/588). The fill-bar stop touch counts as a loss (l.508-510). After that, stop-first touch checks (l.458-461).
- **Target / exit:** bTgt='Opposite level': the other side of the 08:00 range if it is beyond entry and >= minRR(1.0) x risk, otherwise entry +/- bRR(2.0) x risk (l.562-563, 589-590). 'Fixed RR' always uses bRR. TP is based on the planned entry and is never checked on the fill bar. Neutral close at the next 09:00 window start (l.470-472).
- **Position rules:** Same as A: at most one fill per window. A 'missed' cancel happens if TP is touched before the fill. Unfilled setups and the armed limit are cancelled at the first bar after 11:59 (l.491-492). An open trade continues past 12:00 until SL/TP or the next 09:00 bar, where it is closed neutral (counted in Trades, not in W/L). No reversal or cooldown.
- **Timeframes:** 1m chart. The 08:00 range comes from chart bars, which on 1m is equivalent to the 60m 8 AM candle.
- **Sessions (New York):** Range 08:00-09:00 NY (bars 08:00-08:59); trade window 09:00-12:00 NY (bars 09:00-11:59); all 7 days.
- **Defaults:** entryMode 'FVG edge'; mssLen 2; dispMult 1.5; minFvgTicks 0; slBufTicks 0; minRR 1.0; useB true; bRange 0800-0900; bWin 0900-1200; bTgt 'Opposite level'; bRR 2.0

### Model C: 1H PD-array bias + 5m FVG tap -> 1m IFVG or CISD trigger, market entry (long and short)

*Fully defined by the script (entry, stop and exit):* **yes**

- **Entry:** Bias: cBias = request.security('60', f_pdBias(3), lookahead_on) (l.617, 228-298). It is persistent state; each 1H bar collects events from up to 10 stored 1H FVGs per side, with no size filter. Bullish events: a bullish FVG wicked into with close >= its midpoint, or a bearish FVG closed above (then removed). Bearish events mirror these. Bias becomes +1 if the bar had only bullish events, -1 if only bearish, and is otherwise unchanged. The value is from the last closed 1H bar, and it starts at 0, which means no trades. Zones: every 5m FVG (no size or displacement filter) from the last closed 5m bar (f_htfFvg l.301-304, request l.618) is added on the first 1m bar of the next 5m bar (cFresh l.623, l.801-805). At most 6 zones exist (bull and bear combined, oldest dropped, l.364). A zone dies when a 1m bar closes beyond its far edge (l.377-381). Zone tracking runs on every 1m bar around the clock (l.806, 385-400): tapBar = first touch; ext/extBar = most extreme price inside the zone; cisd = open of the first candle of the latest run of opposite-colour candles at the moment ext was set (bearRunOpen/bullRunOpen l.740-743). Trigger (l.811-830): requires a bar inside 09:30-12:00, no live C trade, cTaken < 1 and bias != 0. Zones are scanned newest first for one with dir == bias, tapped, unused, and bar_index - extBar <= cLook(30). Then either IFVG: this bar closed above the top (low[2]) of a stored bearish 1m FVG (gap >= minFvgTicks) whose middle candle is <= 30 bars old and >= tapBar-30 (l.745-773, 817). Or CISD: close > z.cisd (l.818), which is a level test, not a cross. Shorts mirror this. risk = |close - sl| must be > 0. Order: MARKET entry recorded at the signal bar's close (l.826).
- **Stop:** z.ext - slBuf (long) / z.ext + slBuf (short) (l.819): the extreme printed inside the zone, including the signal bar (zones update before the trigger, l.806). Stop-first touch management from the next bar (l.452-464).
- **Target / exit:** cTgt='Draw on liquidity': dol = cBSL for longs (the lowest untaken 1H pivot high, len 3, of up to 50 stored, l.276-298) or cSSL for shorts (the highest untaken 1H pivot low), as of the last closed 1H bar. TP = dol if it is beyond the close by >= minRR(1.0) x risk. Otherwise, or if dol is na or already passed, TP = close +/- cRR(2.0) x risk (l.822-825). 'Fixed RR' always uses cRR. Neutral close at the next 09:30 window start (l.809-810).
- **Position rules:** At most one C trade per window, i.e. per day: cTaken resets only at the 09:30 window start (l.807-808, 828), never while a C trade is live, and the zone is marked used. The trade is not closed at 12:00. It runs until SL/TP or the next 09:30 bar, where it is closed neutral (counted in Trades, excluded from W/L). No reversal or cooldown.
- **Timeframes:** 1m chart. 60m for bias and liquidity (cBiasTF); 5m setup FVG (cFvgTF, 15m optional). The cLook window is 30 1m bars.
- **Sessions (New York):** Trigger window 09:30-12:00 NY (bars 09:30-11:59), all 7 days. Zone taps and extremes are tracked around the clock, so pre-09:30 taps count.
- **Defaults:** useC true; cBiasTF 60; cFvgTF 5; cWin 0930-1200; cTrig 'IFVG or CISD'; cLook 30; cLiqLen 3; cTgt 'Draw on liquidity'; cRR 2.0; minRR 1.0; minFvgTicks 0; slBufTicks 0

### Model D: order-flow (proxy) absorption at a 15m FVG or key level, market entry, fixed 2R (long and short)

*Fully defined by the script (entry, stop and exit):* **yes**

- **Entry:** Delta (l.627-643): the default 'Candle estimate' sets buyV = vol x (close-low)/(high-low) (vol/2 each if range = 0) and sellV = vol - buyV, with vol = nz(volume). aggrSell needs barVol > 0, barVol >= 1.5 x SMA20(barVol) (the SMA includes the current bar), and sellV - buyV >= 30% of barVol; aggrBuy mirrors this. Location (l.856-871): support = the bar's range overlaps a live bullish 15m FVG zone (f_htfFvg on '15', l.619; max 6 zones; killed on a close through). Resistance = a bearish 15m FVG zone. Any key level within +/-0.25 x ATR14 of the bar's range sets BOTH support and resistance. Key levels: overnight VAH/VAL (18:00-09:30 profile, 50 rows, 70%), overnight high/low, PDH/PDL (daily [1]), and manual levels. Long (l.883-902): while flat, an aggrSell bar at support becomes a candidate, recording its body top max(open, close), its low, and ext = low. The candidate is cancelled if a later bar closes below that low or more than 10 bars pass. The trigger is an aggrBuy bar closing above the candidate's body top within that span. MARKET entry recorded at the trigger bar's close (l.891). Shorts mirror this (l.904-924): an aggrBuy bar at resistance, then an aggrSell bar closing below that bar's body bottom.
- **Stop:** Long: the lowest low since the candidate bar, including the trigger bar, minus slBuf (l.884, 888). Short: the highest high plus slBuf (l.906, 910).
- **Target / exit:** Fixed close +/- dRR(2.0) x risk, with risk measured from the signal close (l.891, 913). Stop-first touch management from the next bar (l.452-464). Neutral close at the next 09:30 window start (l.876-877).
- **Position rules:** One D trade at a time, with no daily cap. Repeated sequential trades are allowed inside 09:30-16:00, including on the bar the previous trade closes, because manage runs first (l.779). Candidates reset at window start and on every bar outside the window (l.873-880). A live candidate is not refreshed by later aggressive bars. The open trade is not closed at 16:00. It runs until SL/TP or the next 09:30 bar, where it is closed neutral. The long branch is evaluated before the short branch. No reversal.
- **Timeframes:** 1m chart; 15m FVG zones; daily bars for PDH/PDL; overnight profile built from 1m bars; optional lower-TF intrabar data (seconds) for 'Intrabar' delta.
- **Sessions (New York):** Window 09:30-16:00 NY (bars 09:30-15:59), all 7 days. The overnight session runs 18:00-09:30, and its VA/high/low are computed on the first bar after it (the 09:30 bar, l.848-854). PDH/PDL follow the symbol's own daily session, not the NY calendar day.
- **Defaults:** useD true; dWin 0930-1600; dZoneMode 'HTF FVG + key levels'; dFvgTF 15; dDelta 'Candle estimate'; dLtf 1; dVolMult 1.5; dDeltaPct 30; dMaxBars 10; dRR 2.0; dTolAtr 0.25 (ATR 14); dOnSess 1800-0930; dVaPct 70; dRows 50; useVA/useON/usePD true; dMan1/dMan2 0 (off); slBufTicks 0

## Data needs

Primary chart: 1m OHLCV. The script is written for 1m and flags any other timeframe, and every bar counter (cLook 30, dMaxBars 10, mssBar+3) is in 1m bars. Higher timeframes via request.security with lookahead_on and [1]: 15m (A liquidity swings, D FVG zones), 5m (C setup FVGs), 60m (C bias and buy/sell-side liquidity), and 1D (D PDH/PDL). The daily bar must follow each symbol's own daily session (CME about 18:00 NY, FX/metals CFDs about 17:00 NY, crypto 00:00 UTC). The 08:00-09:00 range (B) and the 18:00-09:30 overnight high/low and volume profile (D) come from 1m chart bars. Bar volume is required for D; nz(volume) means a symbol without volume never triggers D, and FX/CFD volume on TradingView is tick volume. Optional: lower-timeframe intrabar OHLCV arrays (1S/5S/15S) for D 'Intrabar' delta. The lab has no such feed. mintick is needed for slBufTicks/minFvgTicks (both 0 by default). For a real parity check: historical 1m data from the same feed and symbol the user charts on TradingView. The lab currently has only a synthetic feed, and synthetic volume cannot validate D.

## Engine features needed

- Resting LIMIT entries placed at bar close with no bar-count expiry, cancelled by the strategy (EXIT on the pending order) when (a) the target is touched before the fill or (b) the last in-window bar closes. The cancel must take effect before the next bar's fill check.
- Limit fill on touch at the limit price, or at the open when the bar opens through the limit (the lab already does this, with spread)
- Market entries for C and D (lab: next-bar open) with SL/TP levels fixed at signal time
- Fixed SL/TP brackets with stop-first resolution; no trailing, partials or breakeven
- Strategy-initiated exit at a later time: neutral close at the next window start of the same model (A 20:00, B 09:00, C/D 09:30), possibly holding over weekends
- Per-model counters: one cycle/fill per window (A, B), one trade per window (C), unlimited sequential trades one at a time (D)
- Closed HTF series (5m, 15m, 60m, 1D) available with TradingView lookahead_on+[1] timing: HTF bar k-1 becomes visible from the first primary bar opening inside HTF bar k. The lab's runner batches it with the primary bar that closes at the same instant, which is one 1m bar earlier, so a one-bar lag or option is needed.
- HTF bars aggregated on the symbol's session boundaries, and daily bars on each symbol's daily session
- NY-time session windows with DST, including midnight-crossing windows (20:00-02:00, 18:00-09:30), on all 7 days. Window start = first bar in the window whose previous bar was outside it.
- Bar volume per bar; optional lower-TF (seconds) intrabar arrays for D intrabar mode (not available)
- Pine-compatible indicators: ta.sma, ta.atr (RMA/Wilder), and ta.pivothigh/ta.pivotlow with TradingView tie semantics and len-bar confirmation lag
- Instrument tick size (mintick) for buffers and minimum FVG size
- Bar-index based lookbacks (count bars, not minutes)

## Building blocks

- 1m displacement FVG (A/B variant): bull = low > high[2] and gap >= minFvgTicks*mintick; middle candle same-direction with body >= dispMult(1.5) x SMA20(body)[1] (the SMA includes the middle candle; nz -> 0 during warm-up). Zone top = low, bottom = high[2]. Recorded only if the first candle is at or after the sweep-extreme bar and the middle candle is <= mssBar+3 after the MSS. Invalidated by a close beyond the far edge (unarmed only).
- 1m plain FVG for inversion (C IFVG): same gap test with minFvgTicks and no displacement. Stores the far edge (bear: low[2]; bull: high[2]) and the middle-candle bar. Expires after cLook(30) bars and is inverted by a close beyond the far edge. Not checked on its formation bar.
- HTF FVG (C 5m, D 15m, 1H bias): no size filter and no displacement, from the last closed HTF bar ([1]/[3] offsets). Zone dies on a 1m close beyond its far edge. Cap of 6 zones combined bull+bear (C, D) or 10 per side (1H bias).
- Pivots via ta.pivothigh/pivotlow(len,len), three variants: 1m mssLen=2, stored with pivot bar index (cap 100), lookup = most recent pivot before the sweep-extreme bar; 15m aSwing=2, untaken list (cap 50), 'most recent surviving'; 1H cLiqLen=3, untaken list (cap 50), 'nearest' = min of highs / max of lows
- Untaken-liquidity tracker: a level is removed when a later HTF bar's high > level (or low < level), strictly greater
- MSS: close strictly beyond the most recent opposite 1m pivot formed before the sweep-extreme bar
- Sweep state machine (A/B): wick beyond range level, extreme extension that resets MSS/FVG, direction flip, optional close-back-inside flag
- Session range high/low from chart bars (B 08:00-08:59; overnight 18:00-09:29)
- 1H PD-array bias state machine (respected/disrespected FVG events, persistent bias)
- CISD level: open of the first candle in the latest run of same-colour candles (close<open / close>open), snapshotted when the zone extreme updates
- Overnight volume-profile value area: 50 rows over the session range; each bar's volume is spread evenly over the rows its range covers; POC = first max bin; greedy one-row expansion comparing the next row up vs down, ties going up, to 70%; VAH = top edge of the upper row, VAL = bottom edge of the lower row
- Candle-estimate delta (close location in range x volume) and aggressive-volume flags (vol >= 1.5 x SMA20 including the current bar, |delta| >= 30% of vol)
- ATR(14) RMA and key-level touch tolerance of 0.25 x ATR
- PDH/PDL = daily high[1]/low[1] on the symbol's daily session

## Parity risks

- HTF timing: on TradingView, lookahead_on+[1] (l.616-620) shows HTF bar k-1's values from the first 1m bar inside HTF bar k (e.g. the 19:45 15m bar at the 20:00 1m bar). The lab's runner (strategy_engine/runner.py l.155-156) delivers a closed HTF bar with the 1m bar that closes at the same instant, one bar earlier. Without a one-bar lag, C/D zone creation, C bias/DOL updates and the PDH/PDL switch shift by one 1m bar.
- HTF bar construction: TradingView's 5/15/60/D bars come from its own feed and are aligned to the symbol's session. Daily boundaries differ by asset (CME 18:00 NY, FX 17:00 NY, crypto 00:00 UTC). Symbols with a :30 session start get :30-aligned hourly bars. Lab aggregation must use the same boundaries.
- C and D record entry at the signal bar's close (l.826, 891, 913). The lab fills market orders at the next open, so entry, realised R and the odds of an immediate stop/target hit all differ. SL/TP levels are computed from the signal close.
- A/B fill bar: the script never checks TP on the fill bar (l.453; run() checks only the stop, l.508). The lab checks TP on an intrabar fill if the close is beyond it, and with the full bar range when the bar opened through the limit (gap fill, not intrabar; paper/account.py l.645-655, 800-813).
- Lab triggers limits, stops and targets on bid/ask (half spread) and rounds levels to the tick grid against the account (domain/costs.py limit_triggered). The script uses mid-price touch (low<=entry, high>=tp, low<=sl). With a non-zero spread, fill counts and W/L outcomes differ.
- Neutral closes at the next window start carry no exit price in the script (closeTrade(0), label at close, l.425-427) and are left out of W/L. The lab's EXIT fills at the next open with real PnL.
- The script outputs only Trades/Win/Loss/Win% (Win% excludes neutral closes, l.606). There is no PnL, so parity can only be checked trade by trade (signal time, entry/SL/TP, outcome).
- Gap fills: in the script, TP stays tied to the planned limit price when the fill is at a better open (l.504-505 vs 563). The lab also keeps signal levels, but the realised R differs from the planned R.
- Pivot semantics: ta.pivothigh/pivotlow tie handling (equal highs) must match TradingView. Pivots are confirmed len bars late and stored at the pivot bar. The MSS level from f_pivotBefore can change as newer pivots before extBar confirm.
- Warm-up and history length: var state (bias starts 0, empty pivot/liquidity/zone lists with caps 50/100/10/6) and the stats table build up over whatever 1m history TradingView loaded, which is limited. Compare only over the same date range, after a warm-up.
- Warm-up: displacement uses nz(avgBody[1]), which is 0 for about the first 20 bars, so any same-colour middle candle qualifies. ATR is na for 14 bars (no key-level touches) and avgVol is na for 19 bars.
- ta.atr is Wilder RMA seeded by SMA. avgVol = ta.sma(barVol,20) includes the current bar; avgBody is offset by [1].
- Session handling: time(timeframe.period, sess+':1234567', 'America/New_York') counts a bar as in the session by its open time, with DST and midnight-crossing windows, on all 7 days. Window start is detected against the previous bar (l.652-655), so a data gap spanning windows can skip a reset. The last fill check for an A/B limit is the last in-window bar (fills are evaluated only when active, l.496).
- Bar-count lookbacks (cLook 30, dMaxBars 10, mssBar+3, bar_index - extBar) count bars. Illiquid 1m crypto (ZEC, PUMP, NEAR, HYPE) with missing bars diverges from minute-based logic.
- Volume: D depends entirely on bar volume. TradingView FX/CFD volume is tick volume or absent (nz -> 0 means never triggers). The candle estimate is a proxy, not order flow. The lab's synthetic volume is not comparable.
- Intrabar mode: request.security_lower_tf (l.630) is called inside an if (Pine v6 dynamic request). Seconds data has short history, so older bars get empty arrays and buy = sell = 0, which means no D trades. With dLtf '1' on a 1m chart it only reflects the chart bar's direction.
- The value-area algorithm (row binning with floor/clamp, even volume spread, single-row greedy expansion, ties up, first-max POC) must be copied exactly. It is computed on the 09:30 bar from the 18:00-09:29 bars.
- barstate.isconfirmed gating (l.724) keeps all logic on closed bars, so the history and realtime signal logic match. Alerts fire once per bar close.
- Back-dated drawings: zone boxes start at the HTF FVG's first candle (time[3], l.362), limit boxes at fvgBar-1 (l.567/594), MSS lines at the pivot bar (l.557). They are visual only; signals belong to the detection bar. Drawing caps (500) are visual only.
- HTF liquidity (cBSL/cSSL) is from the last closed 1H bar and may already be taken on the 1m chart. The script then falls back to the fixed RR (dolD > 0 check, l.823-825), which the port must replicate.

## Behaviour found in the code

- Model C taps are not restricted to the trade window: f_updateZones runs on every bar (l.806), so a pre-09:30 tap and extreme qualify. CISD (l.818) is a level test, not a cross, so if price already sits beyond the CISD level, the first 09:30 bar can trigger immediately.
- Model C never checks that the setup FVG lies toward the draw on liquidity, despite the header comment (l.17-19). The only filter is z.dir == bias (l.816).
- The Model C IFVG trigger is not tied to the zone. Any opposite 1m FVG formed within the last 30 bars (and >= tapBar-30) that is closed through on this bar qualifies (l.745-773, 817).
- C and D zones share a cap of 6 bull and bear zones combined (l.364). 5m FVGs form often, so older eligible zones are evicted.
- A/B can arm on an FVG that formed before the MSS, as long as its first candle is at or after the sweep extreme (l.544, 559). If the MSS happens without a qualifying FVG by mssBar+3, no new FVG can be recorded (l.544), and the setup stalls silently in state 1 until a new extreme, an opposite sweep, or the window end.
- A/B cancel the armed limit as 'missed' when the target is touched before the fill (l.502, 511-512). The fill is checked first on the same bar. The lab has no such rule, so the strategy must cancel via EXIT.
- A/B never evaluate the target on the fill bar (manage requires bar_index > t.bar, l.453; run() checks only the stop, l.508-510). A trade whose fill bar touched TP can later be scored a loss.
- A/B: an outside bar sweeping both levels while unarmed ends as a long setup because the low check runs second (l.517-538). Either side can flip the direction before arming.

## Questions this script raises

- **Models C and D record their entry at the signal bar's close, but the lab fills market entries at the next bar's open. How should the port handle this?** Options: Next-open fill (lab rule), keeping the script's SL/TP levels from the signal close; Next-open fill, with the fixed-RR target recomputed from the actual fill price; Convert to a LIMIT at the signal close that expires after 1 bar (fills only if price returns). Recommended: Next-open fill (lab rule), keeping the script's SL/TP levels from the signal close — The script does not address realistic fills. The lab rule is fixed, and keeping the script's levels makes trade-by-trade comparison with TradingView easiest.
- **The script never closes trades at the end of a window. They run until stop/target or until the same model's next window start (A: next 20:00, B: next 09:00, C/D: next 09:30), sometimes across a weekend. What should the lab do?** Options: Faithful: hold, and exit at the next window start (EXIT on that bar, filled at the next open); Flatten at the window end (A 02:00, B 12:00, C 12:00, D 16:00); Flatten at a fixed daily time (e.g. 16:55 NY) and before weekends. Recommended: Faithful as the main instance; add a 'flatten at window end' variant as a separate instance — Faithful keeps parity with TradingView. Overnight and weekend holds carry gap and swap risk the user may not want on prop-style accounts. A variant lets the lab measure the difference from recorded trades.
- **On which instruments should Model D (volume-based absorption) run?** Options: Only instruments with real exchange volume (MNQ1!, BTC, SOL, NEAR, ZEC, HYPE, PUMP); All instruments, accepting tick volume on FX/CFDs (XAUUSD, XAGUSD, EURUSD, GBPUSD, NAS100, US30, SPX500); All instruments, but report tick-volume ones separately. Recommended: Only instruments with real exchange volume; add tick-volume CFDs/FX later as a separate, labelled instance — D's signal comes entirely from the volume and delta proxy. Tick volume (or none, which means zero trades) makes it a different strategy.
- **How should the 'previous day' for D's PDH/PDL be defined?** Options: Match TradingView: the symbol's own daily session (CME 18:00 NY, FX 17:00 NY, crypto 00:00 UTC); NY calendar day (00:00-24:00 NY); RTH day (09:30-16:00 NY). Recommended: Match TradingView: the symbol's own daily session from the catalog — The script uses request.security('D') with high[1]/low[1], so parity requires the symbol's daily bar. Other definitions change the levels.
- **Should the TradingView-parity runs use zero spread/costs?** Options: One zero-cost parity instance plus normal-cost instances; Normal costs only. Recommended: One zero-cost parity instance per model to validate against TradingView, then normal-cost instances for metrics — The lab triggers on bid/ask and rounds levels against the account, while the script uses mid-price touches. Only a zero-spread run can confirm the logic matches before costs are layered on.
- **Which input variants should be instantiated first? (Each variant becomes a separate instance of the same strategy.)** Options: Defaults only (FVG edge, opposite level / DOL targets, IFVG or CISD); Defaults plus CE entry (A/B) and Fixed RR target (A/B/C) variants; Defaults plus C 'IFVG only' / 'CISD only' and D 'HTF FVG only' / 'Key levels only'. Recommended: Defaults only at first; add variants once the default port passes the parity check — The script defines many option combinations but gives no guidance on which to test. Starting with defaults keeps the parity check tractable.
- **The script's D 'Intrabar (lower TF)' delta mode needs seconds data that the terminal does not have. Port it now?** Options: Port only 'Candle estimate' now; defer 'Intrabar'; Port both, with 'Intrabar' disabled until a seconds/tick feed exists. Recommended: Port only 'Candle estimate' now; defer 'Intrabar' — It cannot be tested or matched to TradingView without a seconds-level feed.
